## Face de book

### This project is an interactive application showing its users how easily information typed inside a browser can quickly be used againsnt you. This project is by no means an actual phishing page, hence why I did not commit to replicating the Facebook landing page 1 to 1.

For this mini-project I was tasked to create an app that deals with data inputted by the user. Which is why I wanted to try my hand at making a simple phishing website to see how easy it is to deceive people. I’m putting a quick disclaimer that I’m not doing this out of malice but rather because I’ve fallen victim to a couple scams in the past myself. I wanted to experience the thrill of what a person who does this on the daily could possibly get out of deceiving people constantly, is it fun? Could this perhaps make me love coding a little more? Such are the questions I was asking myself before tackling this project.
As mentioned, I intended to make my application to deceive the user to enter their information, so I tried to make the home/login page’s appearance as close as possible to the old Facebook landing page. That was before I quickly decided to give up on that idea so I could spend more time focusing on understanding how to handle data and passing it around whether it was through Json files or session data. This interactive experience’s goal was also a way to raise awareness to how you should be careful of where you put your information on the net. This project also served as learning experience for myself since I was not familiar with session data and referring to python files through html.

I first started with building my html files so I could append my other files to the base.html to keep things dynamic. Then in my python file, I created 3 simple functions; one for the login page, one for the index and one for the page revealing the “scam”. The login function essentially had methods such as POST and GET tied to the form residing on the html page, I would then make it so whatever was typed in the form would send it back to the browser in form of a dictionary key and sending the user to the scammed page whether they typed something or not. In my other function handling the scam reveal page, I used an if statement to make it look through the dictionary key and if there is nothing inside those keys, or if one of the fields is missing information, send the user back to the login page, or else they would get sent to the page with all the session data saved. I then used that session data to display it on the reveal page to ask the user a fake ransom.

If I were to do a similar project like this in the future (hopefully not), I would find a way to store all users’ “data” inside a Json file or find a better incentive to make users pay up the ransom.
